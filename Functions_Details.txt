1. format_currency(amount)
   PURPOSE:
   Converts numeric currency values into human-readable currency strings with
   appropriate scaling (Billions, Millions, Thousands, or regular).
   
   TAKES:
   - amount (float/int/None): The numeric value to format as currency
   
   RETURNS:
   - str: Formatted currency string (e.g., "$1.5M", "$500.00", "$0.00")
   
   EXAMPLE:
   >>> format_currency(1500000)
   '$1.50M'
   >>> format_currency(None)
   '$0.00'

---

2. format_number(value)
   PURPOSE:
   Formats numbers with thousand separators for better readability in displays.
   
   TAKES:
   - value (int/float/None): The numeric value to format
   
   RETURNS:
   - str: Formatted number string with commas (e.g., "1,000,500")
   
   EXAMPLE:
   >>> format_number(1000500)
   '1,000,500'
   >>> format_number(None)
   '0'

---

3. sanitize_id(value)
   PURPOSE:
   Validates that an identifier contains only safe characters (alphanumeric,
   hyphens, underscores) to prevent SQL injection attacks.
   
   TAKES:
   - value (str): The identifier string to validate
   
   RETURNS:
   - str: The validated identifier string if valid
   
   RAISES:
   - ValueError: If the identifier contains invalid characters
   
   EXAMPLE:
   >>> sanitize_id("CUST-1001")
   'CUST-1001'
   >>> sanitize_id("CUST'; DROP TABLE--")  # Raises ValueError

---

4. escape_sql_string(value)
   PURPOSE:
   Escapes single quotes in SQL strings to prevent SQL injection attacks by
   doubling single quotes.
   
   TAKES:
   - value (str): The string value to escape for SQL usage
   
   RETURNS:
   - str: The escaped string with single quotes doubled
   
   EXAMPLE:
   >>> escape_sql_string("John's Policy")
   "John''s Policy"

---

5. generate_calc_id()
   PURPOSE:
   Generates a unique calculation ID for premium calculation records.
   Format: C-YYMMDDHHMMSSxx (max 17 characters to fit VARCHAR(20)).
   Uses timestamp and MD5 hash suffix for uniqueness.
   
   TAKES:
   - None
   
   RETURNS:
   - str: Unique calculation ID (e.g., "C-260914150230AB")
   
   EXAMPLE:
   >>> calc_id = generate_calc_id()
   >>> len(calc_id) <= 20
   True

6. call_agent(agent_fqn, messages, thread_id=None, parent_message_id=None)
   PURPOSE:
   Calls a Snowflake Cortex Data Agent via the SNOWFLAKE.CORTEX.DATA_AGENT_RUN
   SQL function. Constructs JSON request payload, executes through Snowpark
   session, and extracts text response and metadata.
   
   TAKES:
   - agent_fqn (str): Fully qualified name of the Cortex Agent
                      (e.g., "INSURANCE_MGMT_SYSTEM.CORE.CLAIMS_TRIAGE_AGENT")
   - messages (list): List of message dicts with "role" (user/assistant) and
                      "content" (text) keys
   - thread_id (str, optional): Previous conversation thread ID for continuity
   - parent_message_id (str, optional): Parent message ID for conversation threading
   
   RETURNS:
   - tuple: (response_text, thread_id, message_id)
     * response_text (str): The agent's text response
     * thread_id (str/None): Thread ID for maintaining conversation context
     * message_id (str/None): Message ID for tracking conversation flow
   
   AGENT EXAMPLES:
   - "INSURANCE_MGMT_SYSTEM.CORE.EXECUTIVE_INSIGHTS_AGENT"
   - "INSURANCE_MGMT_SYSTEM.CORE.CLAIMS_TRIAGE_AGENT"
   - "INSURANCE_MGMT_SYSTEM.RISK.CHURN_PREDICTION_AGENT"
   - "INSURANCE_MGMT_SYSTEM.PREMIUM.PREMIUM_CALCULATION_AGENT"

7. render_agent_chat(agent_key, agent_fqn, agent_label, sample_questions, 
                     system_prompt=None)
   PURPOSE:
   Builds a reusable Streamlit UI component for chatting with Cortex Agents.
   Includes pre-configured quick-question chips, conversation history display,
   message input field, and clear-chat functionality. Manages session state
   for thread continuity.
   
   TAKES:
   - agent_key (str): Unique key for session state (e.g., "exec", "claims", "risk")
   - agent_fqn (str): Fully qualified name of the Cortex Agent
   - agent_label (str): Display name for the agent (e.g., "Claims Triage Agent")
   - sample_questions (list): List of pre-configured question strings to display
                              as clickable chips
   - system_prompt (str, optional): System instruction to prepend to user messages
   
   RETURNS:
   - None (renders Streamlit UI components directly)
   
   SESSION STATE KEYS CREATED:
   - f"agent_messages_{agent_key}": Stores message history
   - f"agent_thread_{agent_key}": Stores current thread ID
   - f"agent_parent_msg_{agent_key}": Stores parent message ID
   
   EXAMPLE USAGE:
   render_agent_chat(
       agent_key="claims",
       agent_fqn="INSURANCE_MGMT_SYSTEM.CORE.CLAIMS_TRIAGE_AGENT",
       agent_label="Claims Triage Agent",
       sample_questions=[
           "High fraud score claims?",
           "Staged accident patterns?",
           "Pending claims over $10K?"
       ]
   )

8. generate_pdf_report(kpi_data, chart_dataframes, title="Executive Dashboard Report")
   PURPOSE:
   Generates a professional PDF report containing KPI summary table, data tables,
   and chart data. Uses ReportLab library for PDF generation with formatted
   styling. Returns PDF as bytes for download.
   
   TAKES:
   - kpi_data (dict): Dictionary of KPI metrics with keys (metric names) and
                      values (metric values)
   - chart_dataframes (dict): Dictionary of DataFrames to include in report
                              Key: section name, Value: pandas DataFrame
   - title (str, optional): Report title (default: "Executive Dashboard Report")
   
   RETURNS:
   - bytes: PDF document as bytes ready for download
   
   DEPENDENCIES:
   - reportlab.lib (colors, pagesizes, styles, units, enums)
   - reportlab.platypus (document generation components)
   
   PDF STRUCTURE:
   1. Title with generation timestamp
   2. Key Portfolio Indicators summary table
   3. Individual data tables for each DataFrame (up to 50 rows each)
   
   EXAMPLE:
   kpi_summary = {
       "Gross Written Premium": 5000000,
       "Total Claims Paid": 3000000
   }
   chart_dfs = {"Revenue Trend": trend_df, "Loss Ratio": loss_df}
   pdf_bytes = generate_pdf_report(kpi_summary, chart_dfs)

11. fetch_executive_kpis()
    PURPOSE:
    Cached function that retrieves executive-level KPIs from analytics tables.
    Decorated with @st.cache_data(ttl=300) for 5-minute caching.
    
    TAKES:
    - None
    
    RETURNS:
    - tuple: (gwp_data, claims_data, fraud_data)
      * gwp_data (dict): Policy trends KPIs
        - TOTAL_GWP: Total Gross Written Premium
        - AVG_RETENTION_PCT: Average retention rate percentage
        - AVG_GROWTH_PCT: Average growth percentage
        - TOTAL_ACTIVE_POLICIES: Count of active policies
        - TOTAL_NEW_POLICIES: Count of new policies acquired
        - TOTAL_CANCELLED_POLICIES: Count of cancelled policies
      
      * claims_data (dict): Claims performance KPIs
        - TOTAL_PAYOUTS: Total amount paid in claims
        - TOTAL_CLAIMS_COUNT: Total number of claims
        - APPROVAL_RATE_PCT: Approval rate percentage
        - AVG_SLA_DAYS: Average processing days
      
      * fraud_data (dict): Fraud prevention KPIs
        - TOTAL_FRAUD_SAVED: Total amount saved from fraud prevention
    
    QUERIES:
    - INSURANCE_MGMT_SYSTEM.ANALYTICS.POLICY_TRENDS
    - INSURANCE_MGMT_SYSTEM.ANALYTICS.CLAIMS_KPI
    - INSURANCE_MGMT_SYSTEM.ANALYTICS.FRAUD_ALERTS

12. confirm_approve(claim_id, user)
    PURPOSE:
    Dialog function that confirms user wants to approve a claim before execution.
    Updates CLAIMS table and records the approval action.
    
    TAKES:
    - claim_id (str): The claim ID to approve
    - user (str): Current user performing the action
    
    RETURNS:
    - None (Updates database and reruns Streamlit app)
    
    SIDE EFFECTS:
    - Updates INSURANCE_MGMT_SYSTEM.CORE.CLAIMS table
    - Sets CLAIM_STATUS to 'Approved'
    - Records UPDATED_BY and UPDATED_AT timestamp

---

13. confirm_deny(claim_id, user)
    PURPOSE:
    Dialog function that confirms user wants to deny a claim with optional reason.
    Updates CLAIMS table and records the denial action.
    
    TAKES:
    - claim_id (str): The claim ID to deny
    - user (str): Current user performing the action
    
    RETURNS:
    - None (Updates database and reruns Streamlit app)
    
    SIDE EFFECTS:
    - Updates INSURANCE_MGMT_SYSTEM.CORE.CLAIMS table
    - Sets CLAIM_STATUS to 'Denied'
    - Records UPDATED_BY and UPDATED_AT timestamp
    
    USER INPUT:
    - deny_reason: Optional text input for denial reason

---

14. confirm_escalate(claim_id, user)
    PURPOSE:
    Dialog function that confirms user wants to escalate claim to fraud unit.
    Flags claim for fraud investigation and updates status.
    
    TAKES:
    - claim_id (str): The claim ID to escalate
    - user (str): Current user performing the action
    
    RETURNS:
    - None (Updates database and reruns Streamlit app)
    
    SIDE EFFECTS:
    - Updates INSURANCE_MGMT_SYSTEM.CORE.CLAIMS table
    - Sets ESCALATED to TRUE
    - Sets CLAIM_STATUS to 'Escalated'
    - Records UPDATED_BY and UPDATED_AT timestamp
